Python 模拟器按官方 JSON 定义计算地址，不调用 MoonPV 的解码函数。参考客户端通过独立 TCP 连接读取。对照只能验证这些模型和测试数据，不能推导所有设备都兼容。

## 0.3.0 首次接入验证

模型列表命令只读取指定设备的 SunSpec 标记和模型头。测试在基地址 50000 放置同型号的两块电表，核对每个请求的地址和长度，再用列表给出的地址读取第二块电表。另测未知型号、已知型号的非标准长度、空表和末尾模型头读取失败。集成测试共 16 组，发布包演示也使用实际 CLI 执行选表读取。

## 0.2.2 快照读取验证

2026-11-24 在同一本机 TCP 模拟设备上比较两个版本，指定基地址 40000。两次发现均发出 6 次请求，随后各用 3 次请求读取一台逆变器和两块电表。三个快照的寄存器数由 52、107、107 降为 18、55、55，完整 JSON 输出逐字节相同。此处统计的是寄存器数量，未测量现场延迟。

新增的第 14 组 CLI 集成测试让每个模型的第一个无用尾部寄存器不可读，并按官方模型定义核对请求终点。旧版在此模拟设备上收到非法地址错误，新版可读取全部快照。

## 0.2.1 交付验证

2026-11-20 增加 Windows/Linux 预编译包。除源码测试外，CI 会在仓库外的含空格路径解压发布包，清空 PATH 并移除 `MOON_HOME`，执行帮助、模拟演示和 JSON 输出，检查参数错误的退出码、stderr 及缺少可执行文件时的提示。压缩包和文件均记录 SHA-256，`BUILD.json` 记录源码提交。验收输出随发布包提供。

本机 Windows 已完成同样的解压运行检查；云端两种平台的结果以发布版本对应的 Actions 记录为准。该检查证明模拟流程可运行，不证明真实设备兼容性。

## 0.2.0 修复的实际问题

- 电量类型修正为 `acc32`：不再把有效的最大值当成缺失值，也不把未累计值当成有效零电量。
- 为连接和请求增加时限；无效帧、超时及取消后关闭连接。取消排队中的调用不会关闭另一个正常调用的连接。
- 保留设备错误，不再把全部错误归为“找不到 SunSpec”；CLI 不再读失败后返回成功。
- 修复模型链计数边界；验证结束标记长度、固定布局和缩放因子。
- 支持 Model 203 三相电压和同类模型多实例；补齐 JSON 精度、状态及类型测试。
- 修正原测试中的无效“正常帧”，避免负面测试在错误位置提前失败。
- 更正“105 个数据点”为“105 个数据寄存器”，将计划、实测范围和未支持功能分开说明。

## CI 与版本

工作流从固定地址下载相同的 MoonBit 版本并校验 SHA-256，分别在 `ubuntu-24.04` 和 `windows-2025` 执行检查、测试、构建、TCP 集成、参考对照和演示。最新一次运行结果以对应提交的 Actions 页面为准；仅配置工作流不等于 CI 已通过。

首次云端检查发现 Linux 发行包解压后缺少可执行权限。安装器现按官方 Unix 安装步骤恢复 `bin` 与内置 TCC 的权限，Windows 安装不受该修改影响。
